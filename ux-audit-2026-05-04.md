# UX Audit Report — El Viajero (el-viajero.paragu-ai.com)

**Date:** 2026-05-04
**Scope:** Full site — 12 pages, all user flows
**Tooling:** Browser automation, codebase inspection, content analysis

---

## Executive Summary

**9 issues found** — 1 Critical, 3 High, 3 Medium, 2 Low

The site has strong bones: solid design system, cart/wishlist infrastructure, dark mode, currency/language toggles, WhatsApp-first ordering, 404 handler, breadcrumbs. But several functional flows are broken and the visual presentation has placeholder gaps.

## Issues

### CRITICAL

#### C1 — Search broken: header sends `?q=` but tienda reads `?search=`

**URL:** /tienda?q=carpa
**Severity:** Critical | **Category:** Functional

**Description:** The header search form redirects to `/tienda?q=${query}` (line 46 of header.tsx), but the tienda-content.tsx and SearchAndFilters component never read `?q=` from URL searchParams. When a user types in the header search bar and hits Enter, they land on the tienda page with all products showing — no filtering applied.

The SearchAndFilters component has a working `search` state and filterable, but it has no initializer from URL params. The `?search=` param is used nowhere either — the tienda page currently ignores all URL query params.

**Steps to reproduce:**
1. Go to any page
2. Type "carpa" in the header search bar
3. Press Enter
4. See all 34 products instead of filtered results

**Expected:** Products filtered to show only items matching "carpa"
**Actual:** Full catalog, no filtering

**Fix:** In TiendaContent (tienda-content.tsx), read `useSearchParams().get('q')` and pass it as initial value to SearchAndFilters or apply filtering on mount.

### HIGH

#### H1 — Search input on homepage navigates to a product page, not search

**URL:** /
**Severity:** High | **Category:** Functional

**Description:** The homepage search bar (top of page) has a different behavior than the header search. When you type and press Enter on the homepage, instead of redirecting to filtered tienda results, it navigates to a random product page (in testing: /producto/silla-plegable-pescador). This appears to be a form submission defaulting to the first link on the page.

**Steps:**
1. On homepage, type "carpa" in the search field
2. Press Enter
3. Lands on a product page, not search results

**Fix:** Ensure the homepage search input is part of a form with proper onSubmit handler pointing to `/tienda?q=...` like the header does.

#### H2 — Meta Pixel configured with invalid PixelID ("XXXXXXXXXXX")

**URL:** All pages (injected in layout.tsx)
**Severity:** High | **Category:** Functional/Console

**Description:** Console shows `[Meta Pixel] - Invalid PixelID: null` warnings on every page load (3+ occurrences per session). The pixel code in layout.tsx has `fbq('init','XXXXXXXXXXX')` — a placeholder. This fires Meta Pixel with a null ID which triggers console warnings and wastes the page load.

Additionally, the pixel script loads unconditionally (no cookie consent gating), which may violate Paraguayan data privacy regulations.

**Fix:** Either set the real Pixel ID, remove the snippet, or gate it behind cookie consent acceptance.

#### H3 — Product tabs (Descripción / Especificaciones / Envío) don't respond visually

**URL:** /producto/carpa-4-personas
**Severity:** High | **Category:** UX/Visual

**Description:** The product detail page has 3 tab buttons (Descripción, Especificaciones, Envío). Clicking them produces no visible change — no visual feedback, no content swap, no active tab styling. The tabs appear to be non-functional or the content changes are invisible.

**Steps:**
1. Go to any product page
2. Click "Especificaciones" or "Envío" tab
3. Nothing happens visually

**Fix:** Add active tab state with visual indicator (underline, bg color), and render the corresponding content section on click.

### MEDIUM

#### M1 — Product images are SVG placeholders, not real photos

**URL:** /tienda (all products)
**Severity:** Medium | **Category:** Visual

**Description:** All 34 product images point to `/images/productos/*.svg` — vector illustrations, not real product photos. For an e-commerce store, this severely undermines trust. A customer can't evaluate a product visually.

Affected: All products across all 6 categories.

**Fix:** Replace with real product photos. Suggested priority order: Camping items (Carpa, Bolsa de Dormir, Silla), then Pesca items, then Auto/Moto accessories.

#### M2 — Footer links "Envíos", "Cambios y devoluciones", "Medios de pago" go to 404 or FAQ hash without content

**URL:** Footer (all pages)
**Severity:** Medium | **Category:** UX/Content

**Description:** The footer "AYUDA" section has 3 link targets:
- /faq?q=faq → goes to FAQ page but the `?q=faq` param does nothing (no content jump)
- /faq#envios → jumps to FAQ page with hash `#envios` but no FAQ item has `id: "envios"`
- /faq#cambios → same issue, no matching FAQ item id

These create a dead-end user experience: user clicks expecting shipping info, lands on FAQ with no answer highlighted.

**Fix:** Either add FAQ items with matching ids (`envios`, `cambios`, `pagos`) or create dedicated pages for these topics.

#### M3 — "Mi cuenta" link leads nowhere functional

**URL:** Header (all pages)
**Severity:** Medium | **Category:** UX

**Description:** The "Mi cuenta" link in the header exists but the site has no login/account system visible. The accounts page likely redirects or doesn't exist. For an e-commerce site, users expect order history and account management.

**Fix:** Add login/account pages or redirect "Mi cuenta" to WhatsApp order tracking (`/pedido/buscar`).

### LOW

#### L1 — Currency toggle switches between Gs/$ but USD price display sometimes missing or misaligned

**URL:** /tienda, /producto/[slug]
**Severity:** Low | **Category:** UI

**Description:** The currency toggle (Gs/$) works via localStorage. Some products show USD equivalents via PriceUSD component, others don't. On the product detail page, switching to USD shows no price update — the main price always stays in Gs. The PriceUSD component only shows in the catalog cards.

**Fix:** Ensure product detail pages also display converted prices when USD is selected.

#### L2 — Newsletter form submits to `/api/subscribe` but the API route may not persist subscribers

**URL:** / (newsletter section)
**Severity:** Low | **Category:** Functional

**Description:** The NewsletterForm posts to `/api/subscribe`. Need to verify this API endpoint actually stores or forwards the email (checked codebase, functionality depends on database setup). If the subscription isn't stored, user gets a success message but nothing happens with their email.
